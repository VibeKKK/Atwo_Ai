# 行为用例：让「算得对不对」也有判据

## 为什么还要多这一层

前面已经有三层闸门：形状（非空、无占位符）、语法（node --check）、约定（行数、导出名、接口契约）。
这三层能拦住「没写完」「写坏了」「签名对不上」，但拦不住一类更隐蔽的错 —— **它长得完美，但算错了**。

真实的例子（2026-11-16）：

```
输入 humanVerdict({ consensus: 'all-revise', issues: 17 })
输出 「2 个 AI 都认为还要改，共列出 0 个问题」
```

这份产物：179 行、语法正确、五个导出名齐全、在要求的行数区间内。三层全过。
只有真跑一遍，才知道它把 17 数成了 0。而这一句会直接念给用户听。

所以加第四层。它不是更严格的静态检查（那仍是「看」），它是**真跑**。

## 用例文件长什么样

一个 `.mjs`，导出 `cases` 数组：

```js
export const cases = [
  { name: 'n 是数字要原样返回', call: (m) => m.count({ n: 17 }), expect: 17 },
  { name: 'n 是数组要返回长度', call: (m) => m.count({ n: [1, 2, 3] }), expect: 3 },
  { name: 'n 缺失要返回 null', call: (m) => m.count({}), expect: null },
];
```

- `call(m)`：`m` 是被测模块的全部导出。**抛错不算崩溃**，会被捕获下来当成结果。
- `name`：失败时原样出现在报告里，所以写成人话 —— 「n 是数字要原样返回」而不是「case 1」。
- `expect`：三种写法

| 写法 | 判据 | 例子 |
|---|---|---|
| 值 | 深比较 | `expect: 17` |
| 正则 | 对返回值（抛错时对 `'throw:' + message`）做 test | `expect: /17/` |
| 函数 | `expect(got, err)` 返回真值 | `expect: (v, e) => v === 17` |

函数形态收到第二个参数 `err`：被测代码抛错时它是那个 Error，没抛错时是 `undefined`。
所以「这个输入必须报错」也能断言：`expect: (v, e) => !!e`。

## 怎么挂到任务上

在任务正文里加一行：

```
# 1 写 lib/probe_count.mjs：统计一条记录里的条目数

导出 count(rec)……（任务正文）

行为：_probe/count.behavior.mjs
```

这一行会在派活**之前被剥掉** —— AI 不需要知道我们怎么验它，那只是噪音。
落盘之后，验收自动多跑这一层；用例挂了就是没通过，跟语法错一样处理。

JSON 任务格式用字段：`{"text": "...", "behave": "_probe/x.behavior.mjs"}`。

单独验一个文件：

```bash
node packages/accept/bin/accept.mjs lib/probe_count.mjs --behave _probe/count.behavior.mjs
node atwo.mjs check lib/probe_count.mjs --behave _probe/count.behavior.mjs
```

## 什么该写进来

**写判据，不写实现细节。** 用例要能回答「这个函数做出的承诺兑现了吗」，而不是「它是不是照我脑子里的写法写的」。

该写：
- 任务里明确点出的行为（「n 缺失返回 null」）
- 曾经真出过错的边界（那条 17→0 的）
- 让不同产物产生分歧的输入（这类最值得，因为人本来就要裁决）

不该写：
- 精确到空格、标点的输出格式 —— 那是 formatOnly，会逼着 AI 猜你的审美
- 依赖当前时间的断言（会不定时炸）
- 需要联网 / 读真实用户目录的用例（子进程隔离挡不住，但会让验收变慢和不可复现）

## 三件要知道的限制

1. **这一层会执行被测代码。** 前面三层刻意不 import（免得跑顶层代码写盘、开端口），这一层反过来了。所以它跑在**子进程**里：崩了、挂住了（20 秒超时）、副作用搞坏了，都影响不到验收本身。但副作用是真实发生的 —— 只在可信产物上用。

2. **不能替代人。** 用例只能验你已经想到、并且写下来的东西。它抓住的那次 17→0，是因为我恰好想到「数一下条数」。没想到的错，它一样看不见。

3. **用例写错了会骗人。** 我第一版 divergence 用例喂的是 `{case, values}`，而 `mergeDecisions` 吃的是 `{case, groups}` —— 全部返回 0，看起来像产品坏了，其实是验证者没读接口。行为层如实报了 1/5，我才发现是自己的输入形状错。**用例错了，它不会替你兜。**

## 一句话

三层静态检查回答「它像不像一份交付」，
行为用例回答「它做的事对不对」，
异源评审回答「它有没有想偏」。

三件事互不替代。
