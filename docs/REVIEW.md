# 纠错 AI（review）

## 它解决什么问题

程序化验收（`lib/verify.mjs`）只能看**形状**：语法过不过、字数够不够、导出名对不对、参数名符不符合契约。
它看不出「这段话是错的」。

2026-11-15 我自己犯了个真实的错：查了半天 Trae 有没有删除入口，结论写进代码注释「条目级没有删除入口」，
两小时后用户拿一张截图把它推翻了——菜单里明明有「删除任务」。语法全过、字数够、格式对，结论是错的。

所以需要另一种检查：**另一个 AI 来挑错，而且它不能是写的人**。

## 三条硬规则

| 规则 | 为什么 |
|---|---|
| **异源**：评审者 ≠ 产出者 | `reviews/trae-review-trae.mjs.md` 就是 trae 审自己，等于自说自话 |
| **结构化裁决**：必须给 `VERDICT: ACCEPT` 或 `VERDICT: REVISE` | 没有可解析的结论，下游没法自动决定要不要返工，评审就退化成一份没人看的文档 |
| **REVISE 要回流** | 评审说改，得有人按意见去改，否则只是又多一份散文 |

第三条最容易被忽略：只评不改，等于把「发现问题」当成「解决了问题」。

## 怎么用

### 单个文件

```bash
node orchestra.mjs review docs/REVIEW.md
node orchestra.mjs review lib/foo.mjs --author trae          # 声明产出者，评审者自动避开它
node orchestra.mjs review lib/foo.mjs --by workbuddy         # 强制指定评审者
```

终端会打印两行关键信息：

```
[review] 产出者 trae → 评审者 codebuddy（异源）
[review] 裁决：REVISE（问题 6 条）
```

评审原文存档在 `reviews/<评审者>-review-<文件名>-<时间戳>.md`，文件头写了产出者、裁决、问题条数。

### 接进批量流程

```bash
node orchestra.mjs swarm tasks.md --land --review              # 跑完自动评审每个落盘产物
node orchestra.mjs swarm tasks.md --land --review --max-fix 1  # REVISE 自动回流给产出者返工 1 轮
```

`--verify` 和 `--review` 分工很硬，不要混：

| | 看什么 | 谁来判断 |
|---|---|---|
| `--verify` | 形状：语法 / 规模 / 契约 / 导出名 | 程序（`node --check`、正则、apispec） |
| `--review` | 内容：说的话对不对、边界想没想到 | 另一个 AI |

## 怎么读裁决

- `ACCEPT` —— 评审者认为没实质问题。
- `REVISE` —— 有具体问题。**问题条数**是顶层编号项的个数，不是行数。
- **没解析到 VERDICT** —— 评审者没按要求给结论。这一条**不能当成通过**，要人看一眼。

还有个细节：判 `REVISE` 却一条问题都没列，会被标成「评审本身不合格」(`weak`)。这种情况通常是评审者偷懒或输出被截断，不能当有效意见。

## 退出码

`review` 命令不再一律 `exit 0` —— 没有后果的验收不算验收。挂 CI 时看这四个数：

| 码 | 含义 | 该做什么 |
|---|---|---|
| `0` | ACCEPT | 放行 |
| `1` | REVISE | 有问题，改了再来 |
| `2` | 用法错 / 同源评审 / 没有异源候选 | 修命令，不是产物的问题 |
| `3` | **没评成** | 所有异源评审者都失败（超时或报错）。产物状态未知，既不是通过也不是不通过 |

评审者超时是常态，不是意外：同一批通道生成动作用时 p50 只有 14.6~69.5 秒，可评审动作要「读全篇 + 判断 + 按格式给裁决」，实测连续两次撞上 240s / 260s 天花板。所以评审出口一律带换人链（codebuddy → trae → workbuddy → doubao），全挂才算没评成。存档头会写「试过并失败：X、Y」，后来人能看到前面挂了几个，不会以为只有一个人评过。

## 已知限制

- **评审者也会错**。它挑出来的问题需要人过一眼；它说 ACCEPT 也不等于真的对。
- **不同通道能力差很多**。codebuddy（CLI）最稳；trae 会超时；workbuddy 慢但输出干净；豆包走文件信箱。
- **串行执行**。多个通道同时抢 CDP 会串台，并行省下的时间不够赔。
- **只审落盘的产物**。在聊天里返回的一段话审不了，因为没有文件给评审者读。
