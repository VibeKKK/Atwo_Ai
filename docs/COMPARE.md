# 对拍：它是对的，还是它们不一样

验收面板有六层。前五层答的是同一个问题的不同侧面 —— **这个产物对不对**。
对拍答的是另一个问题 —— **同一件事被定义了两次，这两次一样吗**。

## 什么时候需要它

有三种场合，人**说不出期望值**，但能说出一对应该相等的实现：

- **跨层契约**：编译器发"跳转到第 3 字节"，解释器收"跳到第 3 条指令"。两边各自的验收全过，拼起来 200 组随机用例错 70 组。
- **重构前后**：改之前的自己是唯一的参照物。
- **两个 AI 各写一份**：四路同题写产出四份代码，谁对谁错要人读 170 行 ×4；对拍只要它们跑同一组用例，把不一样的地方挑出来。分歧本身就是结论。

## 怎么用

```
node packages/accept/bin/accept.mjs <甲> --behave <用例.mjs> --against <乙>
```

`--against` 必须和 `--behave` 一起给：对拍没有期望值，但需要一组输入。

用例文件格式与行为层完全一样（`cases` 数组，每项有 `name` 和 `call`/`run`/`fn`），
区别是**不需要写 `expect`** —— 写了也不看。

## 输出长什么样

```
对拍    不过（2/6 通过）  all-revise 时问题数必须真的是 17 → 甲 "共列出 0 个问题" / 乙 "共列出 17 个问题"
判定  未通过
```

差异逐条列出**甲怎么说 / 乙怎么说**，不比"分数"。

## 它与行为层的分工

| | 要期望值 | 判什么 | 例子 |
|---|---|---|---|
| 行为（`--behave`） | 要 | 对不对 | all-revise 时问题数必须是 17，实际是 0 |
| 对拍（`--against`） | 不要 | 一样不一样 | 甲说 0 个，乙说 17 个 |

同一份产物可以两层都跑：行为层告诉你"这么写是错的"，
对拍告诉你"另一份写法在这点上和你不同"。

## 一个真实教训

2026-11-16 凌晨，四个 AI 各交一层，每层自己的验收全过，
拼起来 **200 组随机用例错 70 组**。原因是写任务的人（我）
把同一条指令的语义写了两次：

- 给编译器写"跳转参数是字节偏移"
- 给解释器写"跳转参数是指令下标"

没有谁写错，是**契约里同一件事出现了两个版本**。
验收每一层都抓不到，因为每层单独看都自洽。
只有把两层接起来跑随机输入，才会 70/200 地错。

这类错误的特征：**没有人撒谎**。所以它需要一种不看任何人自述的检查方法。

## 它抓不到什么

- 两边都错但错得一样（比如都用了同一个错误的公式）—— 这是**唯一需要人**的地方
- 语义正确但性能差一个数量级
- 输出格式对但叙事顺序反了

对拍只回答一个问题：**这两个东西还是同一个东西吗。**
