# 三值 VM：要"严格强于枚举"，只能动见证这一刀

> 对象：`vm/machine.mjs`（三值栈式 VM，11 个操作码，无 DUP）。
> 前置结论（上一轮）：A/B/C 在「有限三值域上的全函数」层面平凡等价，真正带来能力的是 JZ 与可重复观测。
> 本文不重复那个结论，只回答"在此之上还能不能变强、强在哪、代价多少"。

## 0. 先把"严格强于"钉死，否则四问都会答成玄学

### 0.1 三级判据

| 记号 | 判据 | 形式 | 这一级上"变强"指什么 |
|---|---|---|---|
| **E** | 外延 | A ≽ B ⟺ ∀q∈Prog_B ∃p∈Prog_A：⟦p⟧ = ⟦q⟧，⟦·⟧: D\* → O | 函数类更大 |
| **C** | 代价 | 同一函数类下的指令数 / 状态位数 | 同一函数更便宜 |
| **I** | 内涵 | 语义是否穿过"外延坍缩"这个商映射 | 结果无法事后重建原状态 |

后面每条结论都标明挂在哪一级。换判据结论会翻，这是刻意的——凡不标判据的"变强"都是修辞。

### 0.2 一个计数事实，它先封死了 E 级

**命题 1（枚举上界）**：|D| = 3、n 个输入，则一元函数有 3^3 = 27 个，二元函数 3^9 = 19683 个，
n 元函数共 3^(3^n) 个。查表法在 O(3^n) 空间内实现其中每一个。

**推论 1**：任何只改**载体**（把 |D| 从 3 改成 4、改成 k）的改动，在 E 级上表达力提升**恒等于 0**，
因为枚举的上界随 |D| 一起长，永远追平。这不是"还没找到更强的设计"，是计数使然。

**推论 2**：若"严格强于"只按 E 级定义，那么第 1、2 问必然答 0，第 3 问也答 0
（见证对每个固定程序仍是 D\* → O 的全函数，仍可查表）。
**所以在 E 级下这个题目无解，四问全 0，讨论到此结束。**
唯一有内容的问法，是把判据换成 I 级。下面按这个前提走，并明确写出每条 I 级判据的形式。

### 0.3 I 级判据的形式化（本文的判据）

设 ⟦·⟧_ext : Prog → (D\* → O) 是外延语义，⟦·⟧_int : Prog → (D\* → O′) 是内涵语义，
obs : O′ → O 是观测投影。称内涵语义**不可包装**，若不存在 W 使 ⟦·⟧_int = W ∘ ⟦·⟧_ext。

不可包装 ⟹ 你**无法**把内涵 VM 实现成"现有 VM + 事后处理"。这才是"更强"的可检验形式。

## 1. 载体维度：Belnap 四值 = 两个 bit，所以是"更便宜"，不是"更强"

### 1.1 双向翻译判定（两个方向都写出来）

编码：一格的 4 值 ↔ 两个 3 值格 (p, n)，其中 p =「被告知真」，n =「被告知假」，
T = (1,0)、F = (0,1)、B = (1,1)、N = (0,0)。只用 {0,1} 子集，两个格都不出现 U。

**4 → 3（降级）**：Belnap 的 meet（合取）是 p = p₁∧p₂、n = n₁∨n₂ → 2 条 3 值指令；
join（析取）是 p = p₁∨p₂、n = n₁∧n₂ → 2 条；取反（conflation）是交换两格 → 0 条。
每条 4 值二元指令 ≤ 2 条 3 值指令，**常数倍**。

**3 → 4（升级）**：把 3 值嵌进 {T,F,N} 子集，B 不用，0 代价。

两个方向都存在且常数代价 ⟹ **E 级等价**。这是本节的全部结论，不需要再论证。

### 1.2 它不是新信息，它就是你上一轮的 C

Belnap 四值域在同构意义下就是 2 × 2^op（两个独立的二值坐标，一个读法正、一个读法反）。
所以它不是"三值 + 一个新值"，而是**两个 bit 的笛卡尔积**。
上一轮的 C（`{value, known}`）已经能表示它：`known` 是 p∨n，`value` 是 p。缺少的只是 p 与 n 同时为 1 的那一格。
**推论**：Belnap 没有引入任何 C 表达不了的对象，它只是把 C 的两个极化都点亮了。

### 1.3 唯一真实的收益在 C 级，而且可算

每格信息量：log₂3 ≈ 1.585 bit vs log₂4 = 2 bit。
载 k 格状态空间：4^k vs 3^k。装下同样的状态空间，
4 值需要 k·log3/log4 ≈ 0.792k 格 —— **省 20.8%**；
反过来 3 值装 4 值状态需要 1.262k 格 —— **多 26.2%**。

这就是全部收益：寄存器数省两成。代价立刻出现：

| 代价项 | 3 值 | 4 值 | 倍数 |
|---|---|---|---|
| 二元指令真值表条目 | 9 | 16 | 1.78× |
| 穷举测试输入数（n 个输入） | 3^n | 4^n | 1.33^n |
| n = 20 时的穷举规模 | 3.5×10⁹ | 1.1×10¹² | 约 380× |

**这一行是判决性的**：上一轮把"全、等价性可判定、可穷举"列为这台 VM 的核心优势。
4 值把 n = 20 的穷举从 35 亿次推到 1.1 万亿次——优势在工程上直接消失。
省 20% 寄存器，赔掉整个可穷举性。**这笔交易不划算。**

### 1.4 SQL NULL 的"不适用"其实不是第四个值（这是本节最容易搞错的一点）

Belnap 的 Both 是「同时被告知真和假」——两个**来源**。
SQL 的 NULL 被诟病的是把「未知」和「不适用」揉进同一个符号（Codd 1979 之后的老问题，Date 长期批评）。
但「不适用」不是第四个真值，它是一个**成因标签**：这个格子的取值从没被定义。
把 4 值域加上"不适用"变成 5 值，只是又加了一个 bit 的 tag——还是第 1.3 节的算术，还是 0 提升。

**结论**：载体维度的两个典型诉求（Belnap 的 Both、SQL 的不适用）本质都是"**成因没记**"，
不是"值不够"。它们应该被合并到第 3 问，而不是当成第 1 问来做。

### 1.5 判据与挑战

- 判据：请给出一段 4 值程序 p，使得不存在 3 值程序 q（允许 q 的格数 ≤ 2·格数(p)）满足 ⟦q⟧ = ⟦p⟧。
- 我的断言：不存在。理由就是 1.1 的投影翻译，代价 ≤ 2×。
- 若只要求"q 的指令数 ≤ 常数倍"，则更强：**我断言常数是 2**。可反驳的方式很具体：给一条 4 值指令，其 3 值展开需要 ≥ 3 条。

### 1.6 代价小结

改动量：重写 11 条指令里 6 条的真值表（AND/OR/NOT/PUSH/THRESH/LOAD 的常量域），改加载器常量编码，测试域乘 1.33^n。
提升：E 级 0，C 级 +20.8% 密度、−可穷举性。**比值 ≈ 0。**

## 2. 箭头维度：缺的指令不是"effect 指令"，是 CAPTURE/RESUME

### 2.1 为什么 monad 化在 E 级上是 0

monad 是**类型层**的纪律，不是操作语义的扩展：`M a` 里的 M 在运行期不存在。
把「未知」从值改成 `Either Unknown a` 效果，跑出来仍然是 D\* → D 的函数，只是中间多一层包装。
E 级 0。这也正是 Moggi 1991 那套"notions of computation"的要点：monad 解释的是**计算的分类**，不是**计算的集合**。

### 2.2 handler 也是 0，因为它可消去

代数效应 + handler（Plotkin & Pretnar，见文献表）真正的收益是**组合性**：
同一段程序文本，换一个 handler 就有不同含义。
但 handler 可以消去：把 handler defunctionalize 之后内联展开，得到的仍是同一 ISA 的程序，代价常数倍。
**判据**：请给出一段程序 p，其 handler 消去后指令数增长超过多项式。我的断言：不超过常数倍（每个 handler 展开一次）。
所以 E 级 0，(C) 级只是常数，I 级也 0——因为它改的是"程序文本到语义"的映射族，不是语义本身。

### 2.3 真正表达不了的那一类，和 JZ 无关

现有指令集**表达不了**的程序，长这样（伪语法，handler 需要恢复被打断的计算）：

```
h = handler { choose() ↦ resume(T); choose() ↦ resume(F) }   // 同一个挂起点恢复两次
run (withHandler h (λ(). choose() ∧ choose()))
```

障碍不在三值、不在分支，而在 `resume`：它必须**重新进入**被打断那段计算的中间。
栈式 VM 的配置是 (pc, stack)，被打断时这些帧要么已被弹出，要么在唯一一条线性栈上且不能复制。
要让 `resume` 成立，**配置本身必须成为值**，即 D ⊇ Config。

**这是本节最锋利的一句话**：D ⊇ Config 意味着 D 是无穷集（或至少无界），
于是第 0.2 节的计数上界**失效**——这台 VM 逃出了有限域，进入图灵完备的世界。
而在图灵完备的世界里，"严格强于"这个问题重新变成 Church–Turing：**所有人都一样强**。

所以箭头维度只有两种结局：
把 handler 消掉（0 提升），或者让 D 含 Config（逃出有限域，比较失去意义）。
**没有第三种。**这就是为什么它不该做：它不给你"更强"，只给你"换了一个没法比较的赛场"。

### 2.4 但有一件事 JZ 真的不够：只要"未知短路"，JZ 是够的

如果诉求只是"未知作为一种沿调用链自动传播的效果"（即 `Either`/`?` 算子的 VM 版），
不需要 handler，JZ 就够：约定"表达式求值后立刻 `JZ fail`，fail 处统一 `PUSH 0`"，
这就是 Kleene 短路的标准编译模式，`vm/machine.mjs` 现在的 JZ 语义（值为 0 即跳）恰好直接支持它。
**结论**：箭头维度里便宜的那一半（未知传播）已经实现了，贵的那一半（可恢复的 handler）不划算。

### 2.5 代价小结

改动量：要真做 handler，得加 CAPTURE/RESUME 两条指令并把配置纳入值域，等于重写 VM 并放弃全 / 可判定。
提升：E 级 0（可消去），或换赛场（不可比）。**比值最低，明确不建议。**

## 3. 见证维度：唯一能通过"不可包装"检验的一条

### 3.1 先精确说明"更强"是什么意思

**不是**函数类变大（第 0.2 节已封死）。**是** 0.3 节的不可包装：
见证语义无法由外延结果事后重建，因此无法实现为"现有 VM + 后处理"。
这个"更强"是可证的，不是可辩的。

### 3.2 分离定理（含 9 行可机械检验的反例）

约定：值 F = −1、U = 0、T = +1；`JZ` 在值为 0（未知）时跳（与 `vm/machine.mjs` 现行语义一致）。
输入两个：reg0 = a，reg1 = b。目标函数 f(a,b) = 「a 已知则取 b，否则 U」。

**P（惰性）**
```
0 LOAD 0       ; a
1 JZ   6       ; a 未知 → 直接给 U
2 LOAD 1       ; b
3 HALT         ; 结果 b
6 PUSH 0
7 HALT         ; 结果 U
```

**P′（严格）**
```
0 LOAD 1       ; 先无条件读 b
1 STORE 2
2 LOAD 0       ; a
3 JZ   6
4 LOAD 2       ; 结果 b
5 HALT
6 PUSH 0
7 HALT
```

- **外延相等**：9 组输入逐一比对，输出全同（3 行 a = U 输出 0，6 行 a ≠ U 输出 b）。9 次求值即可验证。
- **见证不等**：在 a = U 的 3 行，P 的支撑集是 {a}，P′ 的支撑集是 {a, b}。
  （P′ 多读了一个**不影响结果**的输入——这正是"为什么"与"是什么"的差别。）

**定理 2（不可包装）**：任何只看到外延表 T: D\* → O 的包装器 W，
在这 9 行上对 P 与 P′ 必须给出**同一个**见证（因为输入相同、表相同），
而真实见证不同。故 W 不存在。

推论：**见证语义严格强于"外延 VM + 后处理"**，且这个严格性只用了 8 条指令就证明了。
顺带说明：这个论证不依赖 JZ 的极性约定——把极性反过来，P/P′ 交换角色，定理不变。
（现行规范里 JZ 的极性在 L3/L4 两份文档里是矛盾的，见 `vm/machine.mjs:5-8`、`:95-98`；好在本文的结论对它是免疫的。）

### 3.3 第二个推论，比第一个更值钱：`unknown` 的 why

上一轮的三值 VM 输出 U 时，信息量是**零**——"不知道"这三个字对下游没有任何用处。
见证维度给出的是：**哪几个输入的最小集合，使得把它们之外的一切任意扰动，输出不变**。
这个集合不是外延表能算出来的：表里 U 就是 U，9 行里没有任何一列记录"是被谁带进来的"。

**这条是本文认为最有可能成立的**，理由不是"听起来更高级"，而是它满足 3.2 的定理形式。

### 3.4 指令集要改什么（最小改法）

值的布局从 `v` 变成 `(v, s)`，s ⊆ V 是支撑集（V = 输入变量集合）。指令语义相应变成：
`(a, s_a), (b, s_b) ⟹ (a⊕b, s_a ∪ s_b)`；`JZ` 额外记录"本次跳转的条件依赖 s_cond"。
三条新指令：

| 助记符 | 语义 | 作用 |
|---|---|---|
| `WHY` | 弹出 v，压入 s（只留支撑集） | 取"为什么" |
| `SUPPORT` | 压入当前值的支撑集 | 观测点 |
| `CUT` | 按支撑集做后向切片，输出最小轨迹 | 出证 |

注意 `CUT` 不是逐行执行的指令，是**收尾时的后向切片**（Weiser 1981 那一套，动态版见 Korel & Laski 1988 / Agrawal & Horgan 1990）。
把它做成指令是个设计选择：让切片本身也在 VM 里，可以被观测、被再切片。

### 3.5 代价（可算，不是形容词）

支撑集有三种粒度，代价差一个数量级：

| 表示 | 每值额外存储 | 每步代价 | 能答什么 |
|---|---|---|---|
| 无 | 0 | O(1) | — |
| 三色污点（可信/可疑/来源） | 2 bit | O(1) | 只答"是否依赖不可信输入"，粗 |
| 位集 | \|V\| bit | O(\|V\|/w) | 精确最小变量集 |
| 位集 + 路径 | \|V\| + O(depth) | 同上 | 还能答"走了哪条分支" |

关键数字：位集并集把每步从 O(1) 变成 O(|V|/w)，于是总代价从 O(steps) 变成 O(steps·|V|/w)。
**这是一次真实的渐近退化**，不是常数因子。用 hash-cons 的持久位集可以把摊还代价压回接近 O(1)，但最坏不变。

规模感（按本仓实际负载估）：一次 swarm 派活，|V| ≈ 任务行数 + 产物行数 ≈ 300，位集 300 bit ≈ 38 B/值，
栈深 < 10，总常驻 < 400 B。**可接受**。真正会炸的是 |V| ≥ 10⁴（整文件级输入），那时必须退回三色污点。

另一个代价，且是最容易被忽略的：**精确最小切片与可穷举性死在同一处**。
精确求"最小"支撑集在一般情况下要枚举子集（2^|V|），实践中对 |V| ≤ 20 可精确。
而 3^20 恰好也是穷举测试的上限（第 1.3 节）。**两者共享同一个边界**——
这不是巧合：它们都是"对输入集合做指数搜索"。所以这台 VM 的精确模式天然只能用在 |V| ≤ 20 的程序上，
超过就该降级为三色污点。**设计时就把这个边界写进接口，比事后发现好。**

### 3.6 判据与挑战

- **判据 A**：请给出一段程序 q 与一个包装器 W，使得 W(外延表(q)) 产出正确的见证。定理 2 说不可能，请反驳。
- **判据 B**（更实用）：给出两个程序，外延表相同、最小支撑集不同，且不是 3.2 那种平凡构造。我给的构造用了 8 条指令、2 个输入，**请给出更小或更"不平凡"的**。
- **判据 C**（代价）：请给出一段程序，使三色污点与精确位集给出**不同**的判定结论。若给不出，说明精确模式在实践中无收益，那就退回三色污点，工程上省一个数量级。

### 3.7 为什么这一条的性价比最高

改动：值布局加一个字段 + 3 条指令 + 每个操作码一行并集规则。**约 60 行改动**（算术部分见 3.4）。
提升：唯一一条满足 E 级以上严格性的（I 级不可包装定理）。
比值：唯一非零的那一项。

## 4. 工程维度：在 atwo 里它解决什么，不解决什么

### 4.1 现有代码里已经躺着三个同一类漏洞，且 if-else 修不了

**(a) `lib/syntax.mjs`：三种"没判"被写成"通过"**

```
:40   if (!src.trim())            return { ok: true, lang: 'skip' }          // 空代码 → 过
:42   if (lang === 'skip')        return { ok: true, lang }                 // 没认出来 → 过
:50   if (!py)                    return { ok: true, lang, skipped: 'no-python' } // 编译器没装 → 过
```
三条 `ok: true` 分别是 T、N、N。**一旦坍缩成 `ok`，调用点再也无法区分"检查通过"和"根本没检查"。**

**(b) `lib/verify.mjs:149`：`checks.every(c => c.ok)`**

四层检查（结构/语法/约定/行为）取 AND。本仓自己记着一次实测：
`humanVerdict` 收到 17 个问题却输出"共列出 0 个问题"——四层全过、答案全错。
这就是 **Both**：同时"被告知真"（全过）和"被告知假"（答错）。`ok: boolean` 在原理上装不下它。
`feedbackFor`（:187）随后只筛 `!c.ok`，于是 Both 状态永远进不了回喂。

**(c) `lib/contract.mjs:145`：`repaired` 这个字段产生了，但没人按它分叉**

`return { ok: true, data, repaired: tag !== 'as-is' }`。其中 `single-quote` 那档是把所有 `'` 换成 `"`——
解析成功 **同时** 内容很可能已被改坏。这是另一个 Both。调用侧一律只看 `ok`，两种状态同权。

### 4.2 "if-else 解决不了"的精确形式

不是"难写"，是**不存在**。信息在坍缩点（`ok = every(...)`）被销毁，
此后任何分支都只是在读那个被销毁后剩下的 1 bit。要恢复，必须**在坍缩之前**带着状态走。
这不是控制流问题，是数据表示问题——正是三值 VM 存在的理由。

### 4.3 具体能解决的三件事（带验收判据）

| # | 问题 | 现在的答案 | 有三值账本后的答案 | 验收判据 |
|---|---|---|---|---|
| 1 | 这次交付的"0"是哪一种 0 | 不知道 | T / F / N / B + 成因 | 随机抽 20 条历史 run，人工标注与账本一致率 |
| 2 | 复核预算该花在哪 | 全花或全不花 | 只对 N 与 B 花第二轮 | 同成功率下调用次数下降 ≥ 30% |
| 3 | 是任务描述、通道、还是验收器的错 | 猜 | 最小切片指向具体层 | 与人工归因一致率 |

第 2 条最实在：atwo 的成本模型是"每次派活 ~7.6K 固定 token"（README 成本模型一节），
如果能证明 N/B 占比 p < 1，只对 p 复核就把第二轮调用从 N 降到 pN。
**这是可测的省钱，不是"更清晰"这种空话。**

### 4.4 不能解决什么（明说）

- **不能让 agent 更聪明。** 三值 VM 不产生新信息，只保存已有信息。
- **不能提高单件活成功率。** 成功率由通道质量决定，账本只让失败可见。
- **不解决 trae 的 8 回合天花板。** 那是 DOM 虚拟化的硬限制。
- **不提高吞吐。** 见证维度是纯开销（3.5 节），收益在"少派无效的活"上，需要靠 4.3 第 2 条兑现。

### 4.5 值不值得造

值得，但**只值得做 3 + 4.1(a)(b)(c) 这一件事**，理由是可测：它把三处"信息在坍缩点被销毁"改成"信息一直带着走"，
且改动在 100 行量级、可单独回归。

## 5. 判定

### 5.1 一句话

**建议改造，只改见证（第 3 问），把载体（第 1 问）降级为见证的顺带编码，放弃箭头（第 2 问）。**

### 5.2 排序（改动大小 ÷ 表达力提升）

| 路径 | 改动量 | 提升（判据） | 比值 | 结论 |
|---|---|---|---|---|
| 见证 provenance | ~60 行（值布局 + 3 指令） | 非零（I 级定理 2） | **最高** | **做** |
| 载体 Belnap 4 值 | ~200 行（6 张真值表 + 加载器） | 0（E）/ +20.8% 密度（C），赔掉可穷举性 | ≈ 0 | 不做；若做见证，`(p,n)` 两 bit 自然覆盖它，边际成本 0 |
| 箭头 handler/effect | 重写（D 含 Config） | 0（可消去）或换赛场（不可比） | 最低 | 明确放弃 |
| 保持现状 | 0 | 0 | — | 只作为基线；4.1 的三处漏洞不会自己消失 |

### 5.3 最小可行改造（建议按这个顺序）

1. **W1**：值从 `v` 变成 `(v, s)`，s 用位集；每个操作码加一行并集规则。**先只做这一条**，其余不动。
2. **W2**：加 `WHY` / `SUPPORT` 两条指令（`CUT` 先不做成指令，先做收尾函数）。
3. **W3**：把 `lib/syntax.mjs` / `lib/verify.mjs` / `lib/contract.mjs` 的 `ok` 换成三值 + 成因，调用点分三支。
4. **不做**：改载体、加 handler。

### 5.4 如果只能做一件事

做 W1 + 4.1(b)：让验收结论从 `ok: boolean` 变成 `{verdict, support}`。
这一步就能覆盖"四层全过、答案全错"这个已经发生过两次的失败模式，
且它同时是第 3 问的最小实例、第 4 问的唯一收益来源。
