# 定位与默认档预算（2026-11-17，用户口述）

## 1. 定位纠正（重要，推翻此前「裁决层」说法）

用户原话：「首先 atwo 是效率优先，其次再是验收，就是把大任务分成可以完美契合的小任务」。

三层顺序据此定死：

1. **效率**（第一）：把一个大任务切成能完美契合的小任务，让并行的每一份都小、都确定、都不互相踩。
2. **验收**（第二）：切得好不好由验收来兜底 —— 产物在不在、能不能跑、几份意见对不对得上。
3. **记账**（第三）：把每次派的消耗与结果记下来，回头用来改派活的策略。

推论（会影响后面的取舍）：

- 「四路并派」不是目的，**拆得开才并**。拆不开的一件大活，硬派四路是浪费（上次征求意见就是这种：四路交出两份、两份意思一样）。
- 之前把 atwo 说成「AI 产出物的裁决层」是**倒因为果**：验收是保障，不是卖点。卖点是「同样时间干更多活」。
- 因此下一步的 P0 不该是「误放行率」，而是**切分质量**：一个任务能被切成几份、每份是否自洽、合起来是否还原原目标。误放行率降为 P1。

## 2. 默认档只准用 0.50x 以下的模型（已落地）

用户原话：「改一下默认模式的积分消耗选择的模型 0.50x 以下的」。

实现（`lib/models.mjs`）：

- 新增 `MAX_DEFAULT_MULT = 0.5` —— 硬上限，不是建议。
- 新增 `MULT` 倍率表（实测自 WorkBuddy 菜单）：`hy3 0.00` / `glm-5.3-flash 0.08` / `deepseek-v4.1-flash 0.11` / `kimi-k3.1-pro 0.97` / `kimi-k3 1.62`；`normModel()` 把四个通道的不同写法归一（`Hy3`/`hy3`、`GLM-5.3-Flash`/`GLM 5.3 Flash`）。
- `multOf()` 对未知模型返回 **null 而不是 0** —— 未知不许当免费花。
- `withinBudget()`：已知且 ≤ 上限才放行；未知一律挡。
- `pickWithinBudget()`：全池扫描取**最小倍率**（池子不按倍率排，trae 的 `DeepSeek-V4.1-Flash 0.11x` 就排在 `GLM-5.3-Flash 0.08x` 前面）。
- `TIERS` 全部改为预算内模型，且 doubao 从 `null`（不切）改为真有模型 —— 原来「不切」等于放弃对这个通道的预算控制。
- `renderTierLine()` 对未知倍率打印「倍率未知」，不再静默留空。

真机确认（`--plan`，只算不切）：

```
▶ 模型：workbuddy→Hy3（0.00x） · codebuddy→hy3（0.00x） · trae→GLM-5.3-Flash（0.08x） · doubao→GLM 5.3 Flash（0.08x）
```

测试：`test/models_budget.test.mjs` 12 条（上限是 0.5 / 倍率值 / 归一化 / 未知返 null / strict 两档全在预算内且倍率已知 / crazy 允许超预算 / 池扫描取最小 / 所选模型必须真在通道菜单池里 / 打印行）。全量 **71/71，110.3s**。
