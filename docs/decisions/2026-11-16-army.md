# 三三制阵型（atwo army）：落地判断与两次真跑

2026-11-16 · dsh-work-replace（rank2）· 授权来源：用户「落地」

## 一 · 为什么做成阵型，而不是给 fanout 加参数

阵型是给「一个 PRD 里有一堆互不相同的单元」用的批次工具，不是给单任务提速的。

| 口径 | 只跑主力 | 三三制 | 结论 |
| --- | --- | --- | --- |
| 单任务墙钟 | 90s | 15 + 90 + 50 ≈ 155s | 慢 72%，单任务别用 |
| 20 单元 PRD（串行 30s/单元 = 600s） | — | 侦察 15 + 主力 20×30/6 并发 + 评审 50 ≈ 280s | 2.1× |

所以它的名字该是「PRD 批次阵型」。判据：单元 ≥2 且互不相同；只有 1 个单元直接拒（reason units<2）。

## 二 · 三段的判据

1. **侦察 1 路（只读）**：只给骨架/风险/核对点，每条强制打 `[候选]` + `source`。侦察说的一切都不是事实 —— 实测本地小模型这条线有 100% 捏造率（pregate 标定），codebuddy 也有 17% 引用对不上。无候选时提示「按 PRD 自己读源码，不要假设」。
2. **主力 N 路（一单元一路，异题并行，只读）**：每路拿一个单元 + `// file: <unit>` 契约块头 + 候选警告 + 「不要越界」。只读是 `READ_ONLY_TOOLS='Read,Grep,Glob'`，不是提示词。
3. **评审 M 路（只找反例，不许重写）**：送审前先过机械闸门 `preGateAll` —— 缺「文件:行」的产物不花评审钱，直接 REVISE（reason `pre-gate`）。

## 三 · 票面语义（三条，都不许偷懒）

1. **value 是「决议」，不是 judgeVotes 的 value。** judgeVotes 的 value 是「可判性」：两票全 REVISE 时它给 1（判得出来，判的是否定）。所以 settleArtifacts 自己算 `ACCEPT→1 / REVISE→-1 / unreviewed→0`，judge 原值另存 `judgeValue`。
2. **state 自己算三态。** judgeVotes 的 `value=-1` 同时表示「到票不足」与「都说要改」，直接抄会把「票不够」报成 REVISE。判据 = 到票率（cast/expected ≥ `votes.arity` 0.8 且非 rosterMissing）+ direction。
3. **僵局判 unreviewed。** 一路 PASS 一路 REVISE 且都到票 → direction 0 → 不替任何一方下结论。空清单也判 unreviewed（不是「全部通过」）。

## 五 · 真跑暴露的四个缺陷（本轮已修）

1. **`--reviewers 0` 静默跑成 1 路**：`Math.floor(Number(x) || 1)` 把 0 / 负数 / 非法全部吞成 1。修法 = CLI 严格解析（非整数或越界直接 `exit 2` 且明说「这次没有派出任何子会话」），`runArmy` 里也不再二次夹（夹一下就把用法错变成静默运行）。
2. **`--reviewers -1` 被 `takeOpt` 当成「没给值」**：后一个 token 以 `-` 开头一律当开关。修法 = `takeOpt` 对 `^-\d` 放行（负数当值），开关仍不许被吃（`--split --dry-run` 那条旧坑有回归断言）。这一条是全局修正，`judge --z -0.5,1` 同时受益。
3. **评审原文丢失**：见第四节。
4. **`--reviewers 9` 被夹成 3 而不报错**：与第 1 条同源，一并改成拒绝。
